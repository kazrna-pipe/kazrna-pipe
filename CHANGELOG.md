# Changelog

All notable changes to KazRNA-Pipe are recorded here. This project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.1.0] - 2026-08-06

Correctness and reproducibility release. Several fixes change analysis
behaviour, not only the plumbing; results produced with 1.0.0 are not
comparable to results produced with this version. See *Results affected* below.

### Fixed

**Pipeline execution**

- Aligned the command-line interface of every Nextflow module with the
  analysis script it invokes. Eight modules passed options their scripts did
  not define, which terminated those tasks immediately.
- Aligned every declared process output with the filename the script writes.
- Differential expression now runs on a merged gene × sample matrix. It
  previously received one single-sample counts file per invocation, which
  DESeq2, edgeR and limma-voom cannot model.
- Added `MERGE_COUNTS`, which assembles per-sample featureCounts output into a
  matrix, stripping the annotation columns and naming each column by sample.
- Replaced a placeholder path in the STAR branch that prevented input staging.
- Populated the `aligner`, `strandedness` and `single_end` metadata fields that
  featureCounts and the DE modules read.
- Salmon emits its per-sample directory rather than a bare `quant.sf`, so
  sample identity survives collection.
- Derived the HISAT2 index basename from the index directory instead of
  assuming a fixed name.
- Wired up `CLUSTERING_AGREEMENT`, which was defined but never called.
- Corrected process section ordering, top-level statements and dynamic
  directive syntax for the current Nextflow parser.

**Analysis**

- Concordance analysis now applies the FDR and log-fold-change thresholds. The
  filter arguments were accepted but never used, so cross-method overlap was
  computed on unfiltered gene lists.
- Split `HISAT2_ALIGN` into alignment, sorting and counting. Both aligners now
  pass through the same `FEATURECOUNTS` process with identical settings.
- The differential-expression design is built from the covariates present in
  the metadata rather than hard-coded.
- Single-cell cluster annotation scores clusters against the marker YAML. The
  marker file was passed to the workflow but not read.
- The CPU and GPU single-cell paths share a normalisation method
  (`--sc_normalization`, default `lognorm`) and the same `leidenalg` build, so
  the comparison between them isolates hardware and implementation.

**Reproducibility**

- Every process runs in a container pinned by immutable digest. Seventeen
  processes previously had no container and executed against whatever was
  installed on the host.
- Published three analysis images to GitHub Container Registry, built from
  `containers/Dockerfile.*`. Each Dockerfile ends with a layer that fails the
  build if a required package is missing.
- `containers/MANIFEST.md` records the digest, build date and size of every
  image, and is regenerated by `containers/build.sh`.
- Fixed a Salmon invocation whose bootstrap replicates made `quant.sf` differ
  between identical runs while nothing downstream consumed them.
- Added `--seed` to HISAT2 and stopped publishing its unsorted SAM, whose
  record order depends on thread scheduling.
- `scripts/python/diff_results.py` compares two runs and reports any difference
  not attributable to timestamps or Salmon's bias-model fitting. It fails when
  it finds nothing to compare.

**Test fixture**

- Regenerated at 200 genes with a negative-binomial count distribution and 40
  differentially expressed genes. The former three-gene fixture was too small
  for DESeq2 to fit a mean-dispersion trend.
- `test_data/README.md` describes the fixture accurately: it is synthetic data
  generated by the scripts in that directory, not a subset of any accession.
- Added `test_data/SHA256SUMS`, verified by CI on every run.

**Documentation**

- Added `data/README.md`, `docs/benchmarking.md`, `CITATION.cff` and
  `.zenodo.json`.
- Removed references to files that did not exist.

### Added

- `tools/check_interfaces.py` — verifies that every module's flags and declared
  outputs match the script it calls. Runs as the first CI job.
- Continuous integration that runs the pipeline end to end under both Docker
  and Apptainer, asserts the expected outputs exist and are non-empty, checks
  that the planted differential signal is recovered, and compares two
  independent runs.
- `docs/benchmarking.md` — workload definition, hardware, and the definitions
  used for speed-up and parallel efficiency.
- Benchmark replication (`--benchmark_replicates`, default 3), with one row per
  replicate so dispersion is computed from the measurements.

### Changed

- Minimum Nextflow version is now 24.04, required by the `resourceLimits`
  process directive.
- Replaced the `check_max()` helper with `resourceLimits`, which the current
  Nextflow config parser supports.
- Strong and weak scaling now describe different workloads: strong scaling
  holds the problem size fixed, weak scaling grows it in proportion to nodes.

### Results affected

Any figure or statistic produced with 1.0.0 should be regenerated:

| Affected | Reason |
|---|---|
| Cross-method concordance, and the three-way core gene set | The significance filter was not applied |
| All gene-level counts | featureCounts strandedness is now set explicitly |
| Cross-aligner concordance | Both aligners are now counted by the same process with the same settings |
| Single-cell clustering | Default normalisation is `lognorm`; Leiden runs through `leidenalg` on both paths |
| Cell-type assignments | Marker-based annotation now runs |

### Reproducibility notes

Counts (`NumReads`) and all differential-expression output are bit-reproducible
between runs. Salmon's effective length and TPM are not: `--gcBias` and
`--seqBias` fit their models on a read subsample, so those two columns vary
slightly. They are excluded from the determinism check, and the exclusion is
recorded in `scripts/python/diff_results.py`.
